# 词汇映射

SillyTavern 的文本净化与局部 AI 改写扩展。用规则直接替换或删除不想保留的词句；需要时只让 AI 改写被规则命中的句子。附带规则预设、范围保护、净化对比、深度清理、更新检查与匿名反馈。

文档分工：本文件面向使用者；代码结构与实现约束见 [ARCHITECTURE.md](ARCHITECTURE.md)，版本差异见 [CHANGELOG.md](CHANGELOG.md)。构建、审计、调试与发布的工具细节见源码仓库的 `DEVELOPMENT.md`（不随发布包）。

---

## 安装

1. 把整个扩展目录放进 `SillyTavern/data/<用户>/extensions/`，目录名可任意（插件按实际加载路径解析自身位置）。
2. 刷新酒馆页面，在「扩展」面板启用「词汇映射」。
3. 顶栏工具栏出现「词汇映射」按钮，点击打开工作台。

**不能只拷 `index.js` 与 `style.css`。** `index.js` 直接按相对路径 `import` `src/` 下的模块，缺 `src/` 插件不会启动（控制台报模块加载失败，不是语法错误）。

## 快速开始

1. 打开工作台，新建或导入一套规则预设。
2. 在「净化」页启用需要的规则合集；普通规则直接替换或删除命中内容。
3. 需要 AI 时到「AI」页开启「启用 AI 改写」，配置接口与模型，并把对应规则的处理方式设为「AI 改写」。
4. 需要自动调用就同时开启「自动触发 AI 改写」；只想手动触发时关掉它，普通规则不受影响。
5. 想确认改了什么，点消息旁的「净化对比」看 Diff、追踪命中规则或撤回净化。
6. 要让旧聊天或世界书按新规则重跑，用「深度清理」。

## 界面

工作台是覆盖层，含五个页面。宽屏导航在左侧竖栏，窄屏在底部。

| 页面 | 负责 |
| --- | --- |
| 首页 | 规则总览与切换、规则条目编辑、批量编辑、状态统计、搜索（实时 + 历史） |
| AI | AI 改写双开关、接口与模型、生成参数、全局提示词、改写诊断、通信记录 |
| 净化 | 标签作用范围、应用标签列表与分组、深度清理入口 |
| 工具 | 预设绑定解析与绑定记录、版本与更新、附加功能（AI 改写快捷键、净化结果楼层数、数据库联动、简繁转换） |
| 反馈 | 运行日志、AI 上下文、深度清理诊断、提交反馈 |

顶栏左侧是当前页标题与说明，右侧依次为导览、主题切换、关闭。600px 以下搜索、编辑分组、编辑规则、子规则四个弹窗改为整屏，并适配刘海安全区；手机端首页每个规则分组用 1px 描边和 14px 圆角包成独立卡片。

主题五档，点顶栏主题图标展开下拉选择，结果持久化：跟随酒馆 / 素白 / 暖米 / 墨夜 / 柔灰。暖米为米色底 + 深灰字 + 赤陶强调色；墨夜为 ayu dark 一脉的中性灰蓝底 + 亮正文 + 柔蓝强调色，底与浅字都抬亮一档，并把绿-红差压到极低以避免冷青感、适合久读；柔灰为 Nord 系冷灰底 + 低亮度冷灰字 + 柔绿强调色；后三者按护眼原则避开纯白纯黑与高饱和色。跟随酒馆时强调色与正文色取自酒馆主题。插件内下拉选项在各主题下都用自己的配色。

输入框、文本域、下拉框统一为 1px 描边 + 卡片同色填充；获得焦点时只把描边换成强调色，不占位、不引起布局抖动。单行与下拉只留横向内边距，多行文本域四边留白，各弹窗一致。下拉菜单出现滚动条时右侧留有间距，不贴住菜单项。

## 规则净化

三种匹配模式：**普通文本**、**简易通配**、**正则表达式**。

- 规则按集合分组，可单独启停、排序、搜索、批量管理。首页规则卡的标记与正文使用和编辑弹窗相同的 13px 字号：标记加粗，正文常规。批量编辑操作按钮按内容宽度左对齐成组，不铺满整行。
- 确认/提示弹窗的正文与按钮、输入框同为正文档（桌面 13px、手机 12px），靠字重区分层级；「移动这条规则」等小弹窗的操作按钮按内容宽度右对齐，主按钮用强调色。
- 首页卡片左侧铅笔直接进编辑，右侧「⋯」菜单为 **上移 / 下移 / 复制 / 移动 / 删除**；复制生成「原名 副本」并追加到末尾。
- 搜索是边打字边搜（220ms 去抖）：框内左侧常驻放大镜，输入后右侧出现清空按钮；下方保留最近 10 条关键词，可复用、单条删除或全部清空，历史存在浏览器本地。
- 编辑规则弹窗顶部可按 **全部 / AI 改写 / 程序改写** 筛选子规则，只影响显示，不改动保存顺序。
- 一条规则可配置多个替换候选，每次命中独立随机选择；不填替换内容则删除命中文本。
- 简易通配用 `*` 匹配一小段内容，`{A,B,C}` 表示多个候选写法。
- 正则支持捕获组替换（`$1`、`$2`）与内联高亮，高亮开启时输入框照常编辑、字号不变；光标贴着 `[]`、`()`、`{}` 任一侧会高亮这一对符号本身（起始与闭合点），不涂中间文本，刚打开弹窗时不会自动高亮；语法错误翻译成中文说明（如「字符组没有闭合，请检查 [ 与 ] 是否成对」）。
- 匹配测试区的命中计数显示在测试框外右上角，展开测试区时可见、收起时隐藏。
- 编辑规则分组时若改了名称或规则，关闭会提醒并可选择保存、放弃或继续编辑。
- 启用简繁兼容后，普通文本与简易通配按词典扩展常见简繁变体，正则里的中文字面字符也参与匹配。

处理顺序固定：**先 AI 局部改写，再程序规则净化。**

## 预设与绑定

一套预设 = 一组规则 + 一套 AI 配置。预设可导入、导出、复制、转移，可设为全局默认；AI 接口预设（Base URL / Key / 模型 / 采样参数）独立管理。

「工具 → 预设绑定解析」有三层绑定，命中顺序 **当前角色 → 对话补全预设 → 全局预设**：

| 绑定 | 作用 |
| --- | --- |
| 全局预设 | 未命中角色或补全绑定时的默认值 |
| 当前角色 | 角色卡命中时使用 |
| 对话补全预设 | 按当前使用的补全预设命中 |

右上角「显示绑定记录」列出历史角色绑定与补全预设绑定；指向已删除预设的条目标为失效，可就地清理。

## 范围保护

两种全局标签模式，二选一：

- **保护特定标签**：跳过列表内标签包裹的内容，只处理标签之外。
- **净化特定标签**：只处理列表内标签包裹的内容。

「应用标签列表」标题行右侧是「新建标签」「新建分组」两个独立按钮。每个分组名右侧为 **滑动开关 + 编辑按钮 + 下拉菜单**：开关控制整组生效，编辑按钮就地改名，菜单提供上移、下移、删除。默认分组不可删除，首尾分组自动禁用无效方向。标签操作收在卡片「⋯」菜单里，菜单在分组框之外展开，下方空间不足时向上弹出。

此外可以跳过用户输入，并保护用户设定描述的编辑区；两项都只影响实时净化，不改变深度清理的处理范围。

## 净化对比

消息旁入口查看当前 Swipe 分支的处理记录，按「原文 → AI 改写（如有）→ 程序规则净化」组织：AI 阶段比较原文与 AI 结果，程序阶段比较执行前后文本；没有 AI 阶段时直接比较原文与程序结果。可看片段或全文、追踪命中规则、随时撤回。全文模式里改写片段按类型着色，与顶部工具行的来源圆点同源、随主题变化。工具行一行内依次是「原文 / 程序 / AI / 手改」四项来源圆点、↑↓ 定位和最右侧的「筛选」开关：来源圆点只作颜色示意，点它不会筛选；原文不计数、圆点与正文同色；程序 / AI 的数字是当前差异里的改写项数，手改是插件产出之后用户连续改动段数（连续一段算一次），撤回后归零、重新净化后重算。点「筛选」会在下方展开一行右对齐的「程序 / AI / 手改」，可多选、选中高亮，再点同一项取消，再点开关折叠整行；未选任何来源时显示全部，选中后只隐藏未选来源的改写块，数字不变。↑↓ 在当前可见改写项之间逐条定位，当前项用与删除线同粗的单层描边高亮并显示「第 N / M 项」，定位不影响勾选。弹窗内的说明文字统一用浅字并在开头带图标，与正文改写区分。开启「规则定位」后点击改写片段，会精确打开改写它的那条规则；规则已删除或改动、旧消息无记录、AI/手动编辑产生的片段会明确显示「找不到对应规则」，不再罗列一堆猜测。消息尾部的透视入口贴在分支计数左侧、与 1/1 同行；分支数变成 99/99 时按实际宽度让位，不遮挡右侧分支切换。

「重新净化」会按当前消息原有的阶段类型重跑：原来有 AI 阶段且总开关开启时重新走 AI 改写再接程序改写，原来只有程序阶段或总开关关闭时只跑程序改写；发起失败不会静默退回程序改写。正文在片段与全文两种模式下共用同一套排版；「⋯」菜单可切换正文字号（小 / 中 / 大）、正文行距（1.5 或 1.8）和段落间距（紧凑 4px / 标准 8px / 宽松 12px），两种模式都生效，选择保存到插件设置。

撤回规则：

- 撤回**不要求**当前正文与记录完全一致。
- 记录里仍在原位、未被手动改动的片段还原成原文。
- 手动改过的片段保持原样；因手动编辑而定位不到的替换直接跳过。
- 正文与记录不一致时，界面提示这次撤回会保留你的改动。

识别到的完整 `<UpdateVariable>` 块不进入正文差异展示。对比文本只保留设置的历史条数范围内（默认 3，可设 1–20）；旧记录退出保留范围后不再提供完整阶段对比，但撤回保护与「切回 Swipe 不重复净化」仍然有效。

## AI 改写

只处理被「AI 改写」规则命中的句子，不是整篇润色。

**前置条件**：酒馆助手（JS-Slash-Runner）可用，且在「AI」页配置了 Base URL / API Key / 模型。插件使用自己配置的接口，不改用 SillyTavern 当前主模型。模型列表里「手动填写」排在「自动拉取」之前；模型下拉右侧的省略号菜单收纳了「手动填写模型 ID / 管理手动模型 / 刷新模型列表」，手动模型可在管理弹窗里逐个清除，自动拉取的模型不受影响。

**两个开关**：「启用 AI 改写」是总开关，「自动触发 AI 改写」只控制普通聊天中的自动调用（默认开启）。关闭总开关后「自动触发」置灰；同时所有「AI 改写」类型规则被过滤，只跑程序规则，流式临时替换一并失效——自动与手动入口都生效。开启总开关后，普通回复、透视里的重新净化和深度清理「程序 + AI 改写」都按同一顺序执行：先按序发起所有 AI 改写，AI 全部完成后再按序执行程序改写；AI 未发出或失败时只给一条带原因的轻提示，不会改跑程序改写。「AI」页连接说明下方也会直接提示这件事，点旁边的 i 图标可查看完整执行顺序。

**范围**：默认在被指定的 XML 正文范围内找命中内容，留空则按整条助手消息处理。按完整句子提取，识别中英文句末标点、引号、括号等边界。完整 `<UpdateVariable>` 块从 AI 目标与上下文中排除，但不改变程序规则的作用范围。

**重新改写**：当前分支仍有原文记录时以该原文为来源，否则用当前正文；符合当前追加格式的尾部内容会保留。正文已改动、无法精确对应时，不做模糊定位，也不覆盖整条旧快照。

**排错顺序**：总开关 → 接口与模型 → 规则是否命中 → XML 标签是否闭合 →（自动调用时）自动触发是否开启。「AI」页提供改写诊断与通信记录（最近 10 次实际调用）。

> 改写会把命中范围内的正文与上下文发送到你自己配置的接口，请自行确认该服务的隐私政策。

## 深度清理

处理**已经存在**的内容，不是接下来新生成的消息。

**范围只有两项**：当前角色卡绑定的世界书、当前角色卡的聊天记录。被 `/hide` 宏隐藏的楼层同样参与，并在复核界面标注「已隐藏」。角色卡正文、用户设定描述、其他角色、其他世界书、其他聊天、Shujuku 数据都不进入。

**规则预设**：开始前可在运行设置里选一个已保存的规则集，本次运行按该预设执行，结束后全局当前预设不变。

**两种模式**：只跑程序规则，或「程序 + AI」。默认先预览、按条编辑建议结果，再决定是否应用；也可选择直接应用跳过复核。

打开或切换聊天不会自动重新净化历史记录。文本比较在后台任务执行，切换复核条目或应用前会等当前比较完成——后台比较不等于零开销。

## 反馈与更新

「反馈」是第 5 个导航页，页内四个标签：运行日志、AI 上下文、深度清理诊断、提交反馈。工具页继续负责版本信息与更新检查，有可用更新时可直接更新并刷新。

运行日志按发生时间正序记录最近 100 条事件，时间取设备当前时区，阶段名与原因、模式、来源都翻成中文；未进入改写流程的空转事件（酒馆试运行、后台生成、没有进行中的生成）会按 30 秒间隔合并成一行，只保留时间区间与条数。

每个日期分隔行后面标出当天的事件条数。日志标题行右侧两个动作：**日期正序 / 日期倒序**（切换后记在本地，下次打开还是这个顺序）、**清空日志**（二次确认后同时清掉内存与本地存储）。提交反馈时仍可通过表单勾选附带插件日志。

反馈支持提交 Bug 与功能建议，可附加运行环境、插件日志、深度清理诊断，也可主动选择图片、PDF、文本或 JSON 附件（最多 5 个，每个不超过 10 MiB）。发送前先展示实际准备提交的 JSON 与文件清单，确认后才上传。

简繁词典装在工具页：状态条显示「未安装 / 下载失败 / 安装成功」，失败时给出原因并提供「重新下载」。

## 兼容与提示

- 适配常规聊天、Swipe、消息编辑、流式与非流式生成。
- 处理 TauriTavern、柏宝箱、LoreFrame、MVU 等扩展场景；这些扩展自身更新后，兼容行为可能随之变化。
- Shujuku 是可选兼容项，不是必需依赖；AI 改写需要酒馆助手提供生成能力。
- 数据库自动净化会在每次行更新前核对所属聊天、消息、隔离空间与目标单元格；切换聊天或目标失效后停止旧任务的后续提交。已发出的单次写入由数据库插件负责，不可撤销。
- 同时启用多个会修改同一段正文的方案时，尽量避免重复处理同一内容。

## 数据与安全

- 深度清理在扫描与复核阶段不改写资源，正式修改发生在确认应用之后；直接应用会跳过复核。
- 设置主键固定为 `ultimate_purifier_ai_rewrite`（改显示名不影响数据），迁移逻辑只处理旧命名空间 `..._modified` 与更早的 legacy 键。
- 匿名反馈里的诊断与文件只在你主动勾选或选择后附加；提交前请确认不含敏感内容。
- 正则与简易通配不要写出能匹配空字符串的规则。
- 不希望被处理的内容，优先用范围标签、跳过用户输入或人设保护明确排除。
